# 产品证据拆解

## 目标

把用户提供或授权访问的一手材料转成可复核的产品拆解。结论必须能追溯到页面、截图、录屏、网络响应、任务状态或源代码。不要保存具体产品的专有流程为通用规则。

## 开始前先做两次判断

### 1. 判断产品类型

先识别产品的主要类型，可再标一个次要类型。产品类型决定证据重点，不改变四层分析框架。

- AIGC 创作工具
- 通用执行 Agent
- 对话陪伴产品
- 交易或任务型产品
- 内容、社区或协作产品
- 开发者工具或基础设施
- 其他，由可见能力定义

读取 [references/product-routing.md](references/product-routing.md)，按匹配类型调整取证与分析重点。不要用类型标签补全页面上没有发生的功能。

### 2. 判断证据是否足够

读取 [references/evidence-gate.md](references/evidence-gate.md)。没有一手产品证据时停止拆解，向用户索取证据。产品名称、媒体报道、宣传页、应用商店介绍和既有常识不能单独通过证据门槛。

至少需要一种可验证的一手来源。

- 覆盖目标流程的连续截图或录屏
- 用户授权访问的真实网站或本地应用页面
- 能还原目标行为的原始代码、测试、日志或结构化数据

证据需要覆盖用户所要求的范围。分析完整创作流程时，只有最终结果截图不算完整；分析单个错误状态时，不必索取整个产品。

如果需要登录、验证码或用户接管，停在登录页并让用户接管。不得读取或输出密码、Cookie、Token、浏览器存储和其他凭证。

## 工作协议

### 1. 锁定目标和操作边界

确认用户要回答的问题、目标流程、用户角色、平台、版本或日期，以及允许执行的动作。对真实产品默认只读。没有明确授权时，不发送消息、不生成内容、不发布、不购买、不充值、不删除，也不改变现有项目状态。

### 2. 建立证据账本

为每个可复核证据分配稳定编号 `E001`、`E002`。记录来源、位置、时间或顺序、可见原文、组件、资产、状态和适用结论。截图应记录文件名或截图号；网站记录页面名称和 URL；代码记录文件及行号；录屏记录时间码。

证据结论只使用以下等级。

- `页面事实`：界面、页面状态、可见网络结果或媒体内容直接支持。
- `代码事实`：源代码、测试、配置或数据结构直接支持。代码存在不等于线上路径实际执行。
- `合理推断`：多条事实能支持，但没有直接记录。
- `尚未确认`：证据不足、冲突未解或无法访问。
- `产品建议`：为改善体验或可靠性提出，不描述为原产品现状。

公开的计划、思考摘要和自然语言回复只能证明产品向用户展示了这些说法。只有资产、状态、工具结果、代码执行证据或页面变化才能证明动作发生。不得声称读取到隐藏思维链。

### 3. 按时间顺序还原行为

从目标范围内最早记录开始，逐条检查用户输入、页面反馈、确认门、选择分支、资产变化、任务状态、错误、恢复入口和最终结果。聊天、画布、资产库、任务列表和预览状态要交叉核对；冲突必须并列记录。

### 4. 执行四层拆解

读取 [references/four-layer-method.md](references/four-layer-method.md)，按下面顺序分析。

1. 用户层
2. 技术层
3. 模型层
4. 数据层

每层都要区分事实、推断、未知和建议，并引用证据编号。上层现象与下层解释不能混写成同一事实。

### 5. 建立跨层关系

把用户动作映射到页面状态、系统或工具执行、模型判断、数据读写和后续交接。特别检查版本、稳定引用、确认记录、幂等、失败恢复、任务中断、额度或权限、结果验证以及状态一致性。

### 6. 形成结论

每项问题写清影响对象、出现条件、证据、严重度和验证办法。产品机会点应来自已观察到的阻力、失败或信息缺口，不能依靠行业套话。

## 分阶段请求

用户可以只要求其中一部分，例如用户旅程、Agent 契约、状态机、数据关系或功能等价 Prompt。仍然先过证据门槛，只读取完成该阶段所需的参考文件。

- 需要完整四层报告或跨层分析时，读取 [references/four-layer-method.md](references/four-layer-method.md)。
- 需要 Agent 契约、模型边界或功能等价 Prompt 时，再读取 [references/agent-analysis.md](references/agent-analysis.md)。
- 需要最终交付时，读取 [references/html-deliverable.md](references/html-deliverable.md)，并以 [assets/report-template.html](assets/report-template.html) 为起点。

不要在用户只要求用户旅程时擅自继续还原 Agent Prompt；不要在用户只要求模型层时扩大到账号、敏感数据或未授权测试。

## HTML 交付规则

最终报告必须是可直接打开的 `.html` 单文件。使用内联 CSS 和必要的内联 SVG，不依赖 CDN。页面应包含证据索引、结论等级图例、四层导航和打印样式。所有图、表、节点和关键结论都应显示证据编号。

如果证据门槛未通过，不生成貌似完整的拆解报告。先返回缺失证据清单和最小补充方案，等用户提供材料后继续。

## 完成检查

- 产品类型已说明，拆解重心与类型相符。
- 目标范围内的证据有编号且可定位。
- 没有用宣传文案或常识补全实际流程。
- 用户层、技术层、模型层和数据层均区分事实、推断、未知和建议。
- Agent 口头完成与资产、状态、结果已交叉验证。
- 失败、中断、修改、返回和重试路径没有被正常主流程掩盖。
- 没有输出凭证、敏感身份信息或隐藏思维链。
- HTML 可独立打开，结构完整，窄屏和打印可读。
