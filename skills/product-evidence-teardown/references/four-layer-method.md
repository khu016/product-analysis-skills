# 四层产品拆解方法

## 用户层

回答用户想完成什么、做了什么、看见什么、需要决定什么、结果怎样改变，以及失败后能做什么。

### 必查内容

- 入口、目标用户和使用场景
- 原始需求、输入形式和学习成本
- 主流程、修改流程、失败与中断流程
- 页面反馈、按钮、表单、卡片、进度和错误
- 用户确认门、可逆性、返回与退出
- 用户情绪、想法和痛点
- 结果可见性、可控性和可信度

用户情绪和想法通常属于合理推断。写明触发它的页面事实，不把推测写成用户原话。

### 建议产物

- 用户旅程证据表
- 三泳道流程图，泳道为用户、产品界面、系统结果
- 关键决策和失败恢复表
- 体验问题与机会点

## 技术层

回答界面背后可观察的系统如何组织状态、任务、工具和错误。只还原功能行为，不猜私有基础设施。

### 必查内容

- 页面、模块、服务或工具的功能边界
- 同步与异步任务、进度和状态机
- 工具调用前置条件和用户授权
- 成功验证、失败分类、重试、取消和幂等
- 任务状态、页面状态、资产状态的一致性
- 权限、额度、计费和外部副作用
- 日志、错误提示和可恢复性

官方名称不可见时使用功能性占位名称，并注明不是官方名称。自然语言计划不等于工具实际调用。

### 建议产物

- 功能模块表
- 状态机
- 工具契约表
- 正常、失败和中断时序
- 状态冲突矩阵

## 模型层

回答模型或 Agent 接收什么、判断什么、调用什么、输出什么、如何验证和交接。不得声称读取隐藏思维链或官方 System Prompt。

### 必查内容

- 实际出现的 Agent、加入和退出时机
- 用户当前输入、长期信息、项目上下文、上游产物、公共知识、运行时结果
- 可观察判断、确认门和停止条件
- 模型或生成能力选项及限制
- 工具选择、结果解释和质量验证
- 用户修改后的重入、局部重做和下游失效
- 下游交接和未解决问题

只有页面、代码或运行结果支持时才能确认 Agent 或模型存在。没有具名下游时使用协调层或页面模块，不虚构角色。

### 建议产物

- Agent 清单
- Agent I/O 契约卡
- 输入、判断、工具、输出、交接图
- 功能等价 Prompt 和规则证据追溯表
- 最小测试集

需要这些产物时继续读取 [agent-analysis.md](agent-analysis.md)。

## 数据层

回答产品保存了什么、谁生产、谁消费、如何引用、怎样更新，以及冲突和隐私风险在哪里。

### 必查内容

- 核心实体、字段、对象和状态
- 数据生产者、消费者和更新时间
- 版本、历史记录和来源追踪
- 角色、场景、文件、任务或结果的稳定引用
- 一对一、一对多和派生关系
- 修改、覆盖、失效、删除和恢复规则
- 只写不读、只读不写和重复字段
- 敏感数据、权限、保存期限和用户控制

页面没有字段名时可以使用语义化名称，但要注明为推导设计。空资产页、未同步状态或缺失引用不能自动解释成后端故障。

### 建议产物

- 全局上下文字段表
- 数据生产者与消费者表
- 实体关系图
- 数据生命周期和版本图
- 一致性、隐私与可追溯性问题

## 跨层分析

对每个关键用户动作建立下列映射。

` 用户目标 → 页面动作 → 页面反馈 → 系统或工具结果 → 模型判断 → 数据读写 → 下一状态 `

每个节点引用证据编号。不能确认的连接使用虚线或“尚未确认”，不要为了让图完整而补箭头。

## 问题优先级

- 阻断：用户无法继续或可能发生不可逆损失。
- 高：结果可信度、费用、隐私或核心任务明显受影响。
- 中：增加理解、等待或返工成本，但有替代路径。
- 低：局部文案、视觉或效率问题。

机会点必须包含对应问题、目标用户、改进机制、验证指标和证据编号。
