# Agent、模型和功能等价 Prompt 分析

仅在用户要求模型层、Agent 契约或功能等价 Prompt 时读取。

## Agent 识别

按时间顺序记录实际出现的 Agent。每个 Agent 需要证明名称或角色、触发者、接管点、交接点和是否重入。不要预设 Agent 数量。

## 六类输入

1. 用户当前输入
2. 用户长期信息
3. 项目全局上下文
4. 上游 Agent 输出
5. 平台公共资产、规则和能力
6. 工具或运行时结果

每项标明必填、可选、条件输入或未知，并给出生产者、版本和证据等级。

## 五类输出

1. 用户回复
2. 页面组件
3. 文字、视觉、音频或视频资产
4. 结构化字段和状态写入
5. 下游任务与交接包

Agent 声称完成只能证明回复存在。完成状态还需资产、数据写入、验证结果和用户确认。

## 工具契约

没有官方名称时使用 `<功能性工具名称>`。为每项写调用时机、必填参数、调用前检查、成功结果、验证、失败分类、重试、幂等、状态写入和副作用。

没有执行证据时，公开计划只能标为计划或判断摘要。余额、安全、失败和取消没有样本时保留未知，建议规则不得写成原产品事实。

## 状态机

按证据选择状态，不要求固定数量。常见候选包括等待输入、规划、等待确认、执行、验证、完成、失败、重试、中断、交接和状态同步失败。

每个状态说明允许动作、禁止动作、进入条件和退出条件。生成类 Agent 不能从执行直接进入完成，必须经过结果验证。用户中断后不得继续发起新调用。

## 功能等价 Prompt

功能等价 Prompt 复现可观察行为，不冒充官方原文。至少覆盖角色、目标、边界、输入、上下文读写、工作流程、工具规范、用户确认、结果验证、修改回退、异常、中断、状态机、交接、完成条件和输出格式。

每条关键规则归入事实规则、推断规则、建议规则或未知，并建立规则到证据的追溯表。

## 最小测试

至少覆盖正常输入、必要输入缺失、局部修改、工具失败、用户中断、页面与全局状态冲突。涉及生成额度时增加余额不足和重复请求测试。每个测试写输入、初始状态、预期判断、预期工具、状态变化和禁止行为。
