# HTML 交付规范

## 文件要求

- 从 `assets/report-template.html` 复制或改写。
- 输出一个可独立打开的 UTF-8 `.html` 文件。
- CSS、图例和必要脚本内联，不依赖网络字体、CDN 或外部组件。
- 如果需要图片，优先使用相对路径链接到用户已有证据；不要无必要复制或内嵌大图。
- 文件名使用产品的用户可见名称和拆解范围。通用 Skill 本身不得把任何案例产品名写入模板。

## 必须出现的区域

1. 标题、目标、日期和查看范围
2. 产品类型及本次分析重心
3. 证据覆盖与缺口
4. 证据索引
5. 用户层
6. 技术层
7. 模型层
8. 数据层
9. 跨层流程或关系图
10. 状态冲突、失败和未知事项
11. 体验问题和产品机会点
12. 最值得继续验证的问题

用户只要求某一阶段时，可以省略没有要求的详细表格，但保留四层导航和未分析说明，避免让局部报告看起来像完整结论。

## 表达规范

- 用 `fact`、`code-fact`、`inference`、`unknown`、`recommendation` 样式显示证据等级。
- 每个结论紧邻证据编号。
- 表格在窄屏可横向滚动。
- 流程图使用内联 SVG、HTML/CSS 或预渲染图片。若使用 Mermaid 源码，必须同时提供无需网络即可读的文本或表格版本。
- 用户情绪与想法用推断样式，并允许在 HTML 中保留“待用户补充”字段。
- 机会点写明原问题、方案、预期指标和证据。

## 视觉与可访问性

- 使用语义化标题、`nav`、`main`、`section`、`table` 和 `figure`。
- 正文对比度达到可读水平，颜色不能成为证据等级的唯一标识。
- 提供跳转导航、打印样式和长表格表头。
- 不使用交互来隐藏唯一版本的关键证据。

## 交付前检查

- 浏览器能离线打开。
- HTML 标签闭合，目录锚点有效。
- 页面没有模板占位词。
- 证据编号在索引中都有来源。
- 图片和本地链接存在。
- 打印预览不截断关键标题和表头。
