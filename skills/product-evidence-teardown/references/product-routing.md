# 产品类型路由

选择一个主要类型，必要时增加一个次要类型。类型只决定关注点，所有判断仍需证据。

## AIGC 创作工具

关注输入需求到成品的阶段划分，剧本或提示词、风格、参考素材、模型参数、生成额度、确认门、样例与批量路径、资产版本、角色或对象一致性、生成失败、局部重做、预览、剪辑和发布边界。

模型层重点检查多个 Agent 的职责、上游素材依赖、生成工具、质量验证和下游交接。数据层重点检查素材引用、版本、派生关系和修改后的失效范围。

## 通用执行 Agent

关注目标是否明确、任务如何规划、权限边界、工具选择、执行反馈、长任务状态、审批门、幂等、重试、取消、外部副作用、部分成功和结果验证。

模型层重点检查规划者与执行者边界、上下文压缩、工具结果解释和错误归因。数据层重点检查任务状态、事件日志、凭证隔离、外部对象引用和恢复点。

## 对话陪伴产品

关注角色设定、对话节奏、情绪响应、记忆声明、关系进展、主动消息、用户控制、依赖风险、安全边界和退出机制。

模型层重点检查人格一致性、长期记忆使用、敏感场景处理和事实幻觉。数据层重点检查记忆的来源、可见性、编辑删除、保存期限、敏感信息和跨会话引用。

不要通过制造伤害、诱导依赖或输入真实敏感信息来测试边界。

## 交易或任务型产品

关注搜索、筛选、比较、填写、确认、支付或提交、回执、退款或撤销。所有费用、库存、权限和法律提示按当前页面记录。默认不提交真实订单。

技术层重点检查事务状态、重复提交、超时、补偿和审计。数据层重点检查订单、价格快照、身份、支付状态和数据一致性。

## 内容、社区或协作产品

关注创建、编辑、权限、评论、通知、版本、协作冲突、审核、发布和撤回。默认不发送或发布内容。

模型层重点检查推荐、审核、总结或生成能力。数据层重点检查内容归属、权限继承、版本、事件和删除传播。

## 开发者工具或基础设施

关注安装、配置、核心任务、日志、错误、权限、集成、可观测性、回滚和自动化。运行破坏性命令或改变生产环境前必须获得授权。

模型层仅在产品真实使用模型时展开。数据层重点检查配置来源、密钥边界、状态存储、缓存、遥测和兼容性。

## 混合产品

如果产品跨类型，先按用户主要目标确定主类型，再用次类型补充风险。例如 AIGC 工具同时带通用 Agent 执行能力时，主流程按 AIGC 拆解，工具授权、重试和中断按执行 Agent 重点补充。
